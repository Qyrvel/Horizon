### [GitHub&\#x27;s Rubicon Git storage targets 7,200 pushes per second for AI agents](https://github.blog/engineering/architecture-optimization/inside-githubs-new-git-storage-architecture/) ⭐️ 8.0/10

GitHub has introduced Rubicon, a new Git storage architecture aimed at many AI agents operating concurrently on a single repository. In internal tests, GitHub says it supported 5,000 collaborating agents, 7,200 pushes per second, and low read latency. The system stores Git objects in Azure Blob Storage, manages reference state with Ref-CAS, and uses virtual replicas for reads and writes plus background nodes to compact packfiles. Rubicon is currently in limited private preview, with GitHub saying it will expand availability gradually.

telegram · zaihuapd · Nov 7, 14:12

**「Background」** Git has traditionally stored repository data as packed object files on local disk, with branch and tag references held in files that must be updated under a lock, which limits how many writers can push to one repository at once. GitHub says Rubicon splits that model: Git objects go into Azure Blob Storage, reference state is managed by a component it calls Ref-CAS, and virtual replicas handle reads and writes while background nodes compact the data into packs. The published details are a short vendor description tied to a limited private preview, so the throughput figures are GitHub&\#x27;s own internal test results rather than independently measured performance.

**「Impact」** For teams running many agents against one repository, Rubicon&\#x27;s design targets push and read contention; however, because it is only in limited private preview, the 7,200-push figure is a vendor internal-test claim rather than a generally available capacity guarantee.

### [Coldframe honeypot mimics Danfoss and Dixell refrigeration controllers](https://github.com/hedgerow-dev/coldframe) ⭐️ 7.0/10

Coldframe is a stdlib-only Python honeypot that impersonates Danfoss AK-SM 800A and Dixell XWEB refrigeration controllers, and its author says Shodan indexes both personas as real devices rather than honeypots. It matches header order, certificate fields, TLS versions, and page byte sizes drawn from Shodan records, and it recognizes exploit attempts for CVE-2025-41450, Danfoss&\#x27;s &quot;code of the day&quot; login bypass. Default logins lead to a fake store dashboard with defrost controls, so interactions continue past the first request. Two instances had been live for one day at publication, and the author reported only generic scanners and Shodan&\#x27;s crawler \(refrigerator.census.shodan.io\) so far.

hackernews · hedgerow-dev · Nov 7, 17:27 · [Discussion](https://news.ycombinator.com/item?id=50406292)

**「The flaw behind the persona」** Coldframe&\#x27;s marquee detection targets a known Danfoss weakness: the vendor&\#x27;s advisory DSA-2025-03-01 describes an improper-authentication vulnerability in the AK-SM 8xxA series, remediated in patch 4.2, and CVE-2025-41450 \(published May 8, 2025, CVSS 8.2\) attributes it to datetime-based password generation that enables an authentication bypass in versions prior to R4.2. That is the mechanism behind the &quot;code of the day&quot; login bypass the honeypot records and scores for correctness.

**「Impact」** For ICS and IoT defenders, the project shows that a Shodan fingerprint match is not proof a device is genuine, so inventory and exposure decisions should be checked against the device itself rather than banner data alone.

**「Community discussion」** Commenters questioned the Shodan-derived approach: supriyo-biswas argued that many internet-facing devices are themselves honeypots or already compromised and suggested probing a real vulnerable unit instead. The author responded that supermarkets lack security teams and argued that safe defaults—patching, VPN access, and strong passwords—must come from vendors or installers rather than store managers.
