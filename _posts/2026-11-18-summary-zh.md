### [Java4Shell：OpenJDK Base64 处理曝远程代码执行漏洞](https://calif.io/java4shell/) ⭐️ 8.0/10

安全研究者公开了名为 Java4Shell 的漏洞利用研究，称 OpenJDK 在处理 Base64 时存在无需认证的远程代码执行漏洞 CVE-2026-114938，CVSS 4.0 评分 9.2，且据称已潜伏近四年。受影响版本包括 Java 17（17.0.6 及之后的全部 17 线）、21、25 和 27；标准 Java 8/11 通常不受影响，但 Oracle Java 8 Performance Pack 例外。利用还依赖特定硬件：仅限支持 AVX-512 VBMI 的 x86-64 服务器处理器，大致是 2021 年及以后的 Intel Ice Lake 及更新 Xeon，以及 2022 年及以后的 AMD Zen 4 及更新 EPYC/Ryzen；ARM64 不受影响。该披露目前是研究性利用链，实际风险取决于上述硬件和版本条件是否同时满足。

hackernews · werrett · 11月17日 21:11 · [社区讨论](https://news.ycombinator.com/item?id=50538240)

**「背景」** OpenJDK 的 Base64 解码在 x86-64 平台上会走 HotSpot 的向量化加速路径，利用 AVX-512 VBMI 指令批量处理输入，而 CVE-2026-114938 正出在这条硬件加速解码路径上：据安全厂商的分析，构造的 Base64 数据可覆盖 Java 堆上 62 或 63 字节，从而构成内存破坏。受影响的是 OpenJDK 17.0.6 及之后的 Java 17 更新版，且仅限支持 AVX-512 VBMI 的 x86-64 服务器，利用前提是让存在漏洞的 JVM 解码攻击者构造的 Base64 数据。

**「影响与处置」** 运行 Java 17（17.0.6 及以后）、21、25 或 27 且对外提供服务的组织，应优先排查搭载 AVX-512 VBMI 的 x86-64 主机（Intel Ice Lake 及更新 Xeon、AMD Zen 4 及更新 EPYC/Ryzen），并依据 Oracle/OpenJDK 发布的修复或缓解指引处置；标准 Java 8/11 和 ARM64 通常不在影响范围内（Oracle Java 8 Performance Pack 除外）。社区讨论中有人提出用 \`-XX:UseAVX=2\` 规避，但该说法尚未得到确认。

**「社区讨论」** 评论者认为利用条件虽然具体，但受影响主机仍可能很多；Semgrep 发布了免费检测脚本，针对 HotSpot VM（OpenJDK、Oracle JDK、GraalVM JDK）等五项条件，并称 OpenJ9 和 GCJ 不受影响。另有评论转述未经确认的缓解方法——以 -XX:UseAVX=2 运行 Java，并指出该攻击对网络 RTT 和抖动敏感，低且稳定的延迟更有利于利用。

**「社区讨论」** 有评论认为 server RPC 配合 live、broadcast 的用法比 LiveView 或 htmx/datastar 更自然，补上了 Remix 曾试图解决的「中间层」问题；另有开发者称异步级联下拉示例很有说服力。也有观点指出，官方宣传的「便于 agent 编写」实质上是更好的调试诊断，对手写代码同样有益，并提醒对包体积敏感的团队注意 2.0 的明显增大。

### [Datasette Lite 用 Service Worker 在浏览器运行完整应用](https://simonwillison.net/2026/Nov/17/datasette-lite/) ⭐️ 8.0/10

Simon Willison 发布了 Datasette Lite 的完全重写版：它借助 service worker、Pyodide 和 WebAssembly，在浏览器中运行完整的 Datasette Python 应用，作者称效果已“几乎与真正的服务器端应用无异”。新版本可通过 lite.datasette.io 的 URL 参数加载 SQLite、JSON、CSV 或 SQL 文件，选择 PyPI 上的 Datasette 发布版、GitHub 仓库中的特定 commit/tag/分支、100 多个 SQLite 版本，并从 PyPI 或 wheel 文件 URL 安装插件。它取代了 2022 年那版基于 Web Worker 和 innerHTML 的临时方案，旧方案无法执行注入页面中的脚本，因而依赖 JavaScript 的功能会失效；加载远程数据库和元数据文件仍需目标服务器提供开放的 CORS 头。

rss · Simon Willison · 11月17日 16:48

**「背景」** Pyodide 让 Datasette 这类 Python 应用可以通过 WebAssembly 在浏览器中运行。作者曾在 2022 年发布 Datasette Lite 首版，但当时依靠 Pyodide web worker 模拟请求，再把返回的 HTML 以 innerHTML 注入页面，导致依赖 JavaScript 的功能无法执行；本次基于 service worker 的改写正是针对这一限制。

**「影响」** 对 Datasette 开发者和插件作者而言，现在可以把特定 Datasette 版本或提交、插件以及 SQLite 版本组合进一个链接，用于复现分页等 bug 或演示开发中的功能，而无需部署 Web 服务器；使用远程数据文件时则必须确保其 URL 支持 CORS。

中国汽车工业协会 11 月 16 日发布通知称，受工信部委托，将对一汽、上汽、比亚迪、理想、蔚来、小鹏、小米汽车、零跑等 17 家重点车企的供应商账款支付情况开展第三方调研评估，核查中小企业账期是否不超过 60 天，以及非中小企业以现金和银行承兑汇票支付的比例是否不低于 80%。

telegram · zaihuapd · 11月18日 01:15

**「背景」** 此前，17 家重点车企响应中汽协倡议，公开承诺将供应商支付账期控制在 60 天以内，中汽协还明确账期从验收合格之日起算。此次工信部委托中汽协开展第三方评估，核查的正是这些承诺在实际结算中是否落实。

**「影响」** 向这 17 家车企供货的零部件企业，尤其是中小企业，其回款速度和现金流将直接取决于 60 天账期是否落地，以及现金支付占比能否达到 80%。

### [美芯片新规后，4.8 亿美元字节跳动相关 GPU 贷款被暂停](https://www.bloomberg.com/news/articles/2026-11-17/banks-pause-480-million-chip-loan-tied-to-china-s-bytedance) ⭐️ 7.0/10

美国最新 AI 芯片管制出台后，五家评估该笔融资的银行暂停推进一笔 4.8 亿美元贷款，该贷款原计划为字节跳动在马来西亚的数据中心采购英伟达先进 GPU。借款方为新加坡云服务商 Aolani Cloud，星展集团（DBS）担任牵头安排行；Aolani 表示正与监管机构和融资伙伴评估新规以确保合规。

telegram · zaihuapd · 11月18日 05:11

**「背景」** 美国在 2026 年 11 月发布临时规则，要求可能向中国等受限国家提供计算能力的 AI 芯片出口申请许可证，因此这笔原本用于马来西亚数据中心的英伟达 GPU 采购贷款也要先接受合规评估。

**「影响」** 据银行业者称，在全面评估新规前这笔融资难有进展，部分银行已在内部讨论退出或不参与，因此该数据中心的 GPU 采购资金可能需另寻来源。
