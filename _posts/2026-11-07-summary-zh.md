### [Boson AI 公布 45B 全双工模型 Higgs Realtime Duplex](https://www.reddit.com/r/MachineLearning/comments/1xpn5pv/higgs_realtime_duplex_a_45b_moe_fullduplex_model/) ⭐️ 7.0/10

Boson AI 公布了 Higgs Realtime Duplex：一个 45B 的 MoE 全双工音视频模型，能在持续说话、聆听和看视频的同时，在后台思考、调用工具，并把更难的任务交给更大的后端模型。该模型尚未开放权重，Duplex API 需排队申请；此前的轮次式 Higgs Realtime 现在可用。模型把输入输出切成 160 毫秒块，音频输入和输出分别为每块 1 个和 2 个 token，视频每 6 块约 12 个 token，并用静音块决定接话、打断或保持安静；官方称音视频约每分钟 2.6K token，含思考与工具轨迹为 2.6K 至 5K。Boson 自报的基准（称复现了过半竞品数字）显示，Duplex 的 Big Bench Audio 为 98.9、QIVD 为 56.0，但 OpenAI 的最佳设置在七项中五项领先 1 至 5 分，部分使用最高思考设置，全双工轮次转换仍是 Duplex 最弱项。

reddit · r/MachineLearning · /u/Cali\_Cobarde · 11月6日 20:23

**「背景：轮次式语音模型与全双工」** 目前多数语音模型仍是轮次式的：先听完、等到一轮说话结束，再思考并开口，因此模型在发声时无法继续处理新的输入。Boson AI 此前可用的 Higgs Realtime 也属于这种轮次式方案，此次 Duplex 的差别在于把音频输入输出、视频帧、文本以及思考与工具调用都放进同一条按 160 ms 切分的流里并行推进。

**「影响」** 对希望接入实时语音和视频代理的开发者来说，目前不能直接部署 Duplex：只能申请 API 候补，或继续使用上一代轮次式 Higgs Realtime。Boson 称 45B 前端的设计目标是让一小时模型时间成本不超过十分之一小时人工时间，但在独立基准和 API 开放前，实时延迟、成本与稳定性仍需验证。

### [Muir：以 25MB 固定状态处理 10M token 的线性注意力](https://www.reddit.com/r/MachineLearning/comments/1xplbuu/muir_linear_attention_with_sensitivityallocated/) ⭐️ 7.0/10

Reddit 帖子介绍 Google Research 的 Muir 线性注意力：它结合匹配滤波读出、敏感度分配门控和数值稳定的大分块并行核，把长上下文历史压缩进固定 25 MB 状态。帖子转述的论文结果称，Muir 在 100B token 训练中优于 GDN-2，8K 早期深度召回从 1% 升至 31%，RULER 5 跳变量跟踪根保留率从 28.4% 升至 48.0%，1M token 零样本 passkey 达 90.0%（冷却后 99.4%），并能在 25 MB 状态下流式处理 10M token 而困惑度不漂移。作为对照，1.3B Transformer 在 10M token 时需 2.1 TB KV cache；Muir 还宣称在 32K 训练速度是 Splash Attention 的 2.7 倍。这些数字来自 Reddit 对论文的总结，尚待独立复现和同行评审确认。

reddit · r/MachineLearning · /u/CategoryNormal149 · 11月6日 19:10

**「背景」** 线性注意力用随 token 更新、大小固定的循环状态来替代随上下文长度增长的 KV cache；帖子给出的对照是，1.3B Transformer 在 10M token 时需要 2.1 TB KV cache，而通道门控 delta 模型可把历史压缩到 25 MB 状态。Muir 把 GDN-2 这类通道门控 delta 模型作为直接基线，并针对慢通道能量失衡、写入与擦除的敏感度差异，以及大块并行核的数值不稳定进行改动。

**「影响」** 若结果可复现，受影响最大的是长上下文推理的显存预算：状态固定为 25 MB 后，1M–10M token 流式处理不再需要按序列长度扩张 KV cache，1.3B 模型在 10M token 时的 2.1 TB cache 压力可被规避。开发者在评估 GDN-2 替代方案时，应优先复现 8K 早期召回、1M passkey 和分块核在 fp32 下的数值稳定性；目前这些都只是论文作者结果经 Reddit 转述，尚无独立基准或同行评审确认。

### [百度开源文心 5.5 Flash Base 基座模型](https://www.news.cn/info/20261105/f3bbdb6854f5441ca9fb34062f213875/c.html) ⭐️ 7.0/10

据新华网报道，百度正式开源基座模型文心 5.5 Flash Base。该模型采用 MoE 架构，总参数量 2800 亿，每个 Token 激活 1400 亿参数中的 140 亿参数，预训练使用 33.5 万亿 Token，预训练上下文最长为 128K，微调与推理阶段支持最长 100 万 Token 上下文。报道称其在注意力机制、专家路由和训练目标等环节进行了效率优化，但未披露基准测试结果、许可证条款及权重获取方式等关键发布细节。

telegram · zaihuapd · 11月6日 05:41

**「背景」** 混合专家（MoE）架构把前馈网络拆成多个“专家”，每个 Token 只路由到其中少数几个，因此模型可以用更大的总参数量扩充容量，而单次推理只承担激活参数对应的计算量；文心 5.5 Flash Base 的 2800 亿总参数、140 亿激活参数就是这一口径。基座模型指完成预训练但尚未做指令或对话对齐的模型，通常要经过下游微调才能直接用于任务；这也解释了为何其 128K 是预训练上下文，而 100 万 Token 上下文出现在微调与推理阶段。

**「落地要点」** 对打算自建或私有化部署的团队而言，2800 亿总参数、每 Token 仅激活 140 亿的稀疏结构意味着推理算力需求远低于同等总规模的稠密模型；但 Hugging Face 上的模型卡将其标注为纯文本 MoE 基座模型（base model），并非已对齐的对话模型，实际使用前需自行完成指令微调或后训练，同时核对仓库中的许可条款——本次发布公告本身未给出许可证信息。

### [欧盟指控 TikTok 推荐算法造成“兔子洞”效应](https://www.cnbc.com/2026/11/06/eu-charges-tiktok-harmful-algorithmic-rabbit-hole-effects.html) ⭐️ 7.0/10

欧盟委员会指控 TikTok 的推荐算法造成“兔子洞”效应，违反《数字服务法》，并称其未采取有效措施应对相关风险。委员会要求 TikTok 调整“为你推荐”算法，使其更多依据用户明确偏好，改进控制选项，并定期测试算法。若问题未解决，母公司字节跳动明年可能面临最高相当于全球年营收 6% 的罚款；欧盟认为持续推送相似内容可能影响心理健康，此次指控属于更广泛调查的一部分。
