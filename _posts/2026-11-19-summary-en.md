The flaws are in C-based memory handling, and the supplied material does not name affected Ruby releases or fixed versions. Ruby users should check their distribution&\#x27;s advisory for patched releases and upgrade promptly rather than wait for version details in this summary.

hackernews · runesoerensen · Nov 18, 23:52 · [Discussion](https://news.ycombinator.com/item?id=50554038)

**「Background」** Ruby&\#x27;s October 23 advisory fixed four Regexp engine \(Onigmo\) bugs that GitLab had reported as remote-code-execution risks, tracked as CVE-2026-89078, CVE-2026-93577, CVE-2026-97229, and CVE-2026-110264. CloudLinux issued an alt-ruby update for those same CVEs on October 27. **「Patch urgency」** Ruby deployments that use the affected regular-expression engine or string case-conversion code should upgrade to Ruby 4.0.10, 3.4.13, or 3.3.14; the advisory says proofs of concept show that some of the seven flaws can trigger remote code execution. **「Community discussion」** Commenters focused on encoding-specific failure modes: tptacek described Windows-1252 lacking an uppercase representation for ß, so upcasing can turn it into “SS” and grow a buffer, while pentestercrab posted a Shift\_JIS downcase reproducer. rvz argued that AI-assisted discovery of such C-based bugs shows memory-unsafe languages remain exposed and noted the advisory&\#x27;s credit to Stephan Lipp \(Ada Logics\) and Anthropic; that is commenter assessment, not an advisory conclusion.

### [Nginx HTTP/2 Flaws Enable Unauthenticated Worker Code Execution](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities) ⭐️ 7.0/10

A Wiz report on the nginx HTTP/2 flaws describes a chain of five nginx vulnerabilities plus a Linux kernel bug that, according to the disclosed account, can take an unauthenticated visitor to host root; the HTTP/2 flow-control memory corruption tracked as CVE-2026-123007 allows command execution in an nginx worker. Nginx 1.30.7 and 1.31.9, released Nov. 18, fix 10 CVEs. Rapid7 has published a proof of concept, and no in-the-wild exploitation has been reported. Administrators who cannot upgrade should disable external HTTP/2.

hackernews · speedping · Nov 18, 15:19 · [Discussion](https://news.ycombinator.com/item?id=50547374)

**「What NGINX2Root is」** The flaws are grouped as NGINX2Root, a chain in which five nginx vulnerabilities are combined with a Linux kernel defect to escalate from an nginx visitor to host root; Xint.io reported four of the five. F5 shipped fixes in nginx 1.30.7 \(stable\) and 1.31.9 \(mainline\) on 2026-11-18, along with patched NGINX Plus builds, and distributions such as AlmaLinux have begun publishing updated packages. CVE-2026-123007, the HTTP/2 flow-control memory-corruption bug that permits unauthenticated command execution inside a worker process, is the entry point for that chain.

**「Impact」** Administrators should move to nginx 1.30.7 or 1.31.9; if they cannot upgrade, disabling external HTTP/2 removes the path used by the reported chain. Because the same release fixes 10 CVEs, operators should verify the deployed branch and version rather than patch only the HTTP/2 component.

**「Community Discussion」** Commenters disputed the practical urgency: one noted HTTP/2 is not enabled by default and cited W3Techs data putting adoption at about 12% of servers, while another cited an analysis that exploitation needs 128 Gb of HTTP/2 traffic and specific CPU instructions. A separate commenter criticized the disclosure process, saying the fix landed in the open-source repository a week before the advisory and that a public warning was warranted because disabling HTTP/2 is a simple workaround.

hackernews · ibobev · Nov 18, 14:47 · [Discussion](https://news.ycombinator.com/item?id=50546967)

### [Quad9 Leaves France After DNS Blocking Orders](https://techstackups.com/articles/quad9-leaves-france-dns-blocking/) ⭐️ 7.0/10

The article reports that Quad9 has withdrawn its public DNS resolver from France after DNS-level blocking orders, citing statements from Quad9 and Cloudflare. It frames the withdrawal as evidence that DNS resolvers are the wrong enforcement point for piracy, rather than a fix for the underlying infringement. No new technical system or independent measurement is presented; the case is a policy and infrastructure dispute.

hackernews · ritzaco · Nov 18, 13:18 · [Discussion](https://news.ycombinator.com/item?id=50545958)

**「Earlier DNS blocking in France」** DNS blocking works by making a resolver return no valid address for a domain, which can enforce site blocking without touching the destination server. France has used that mechanism in piracy cases before: a June 2024 order required Google, Cloudflare, and Cisco to block roughly 117 pirate sports sites via DNS. The Quad9 dispute follows a beIN Sports copyright case in which the court ordered DNS blocks and imposed a €1,000-per-day penalty; Quad9 said it would stop serving French users on November 24 rather than comply.

**「Impact」** For users and network operators in France that rely on Quad9, the withdrawal means switching to another resolver or changing DNS configuration. The case also illustrates that DNS filtering mandates can remove a global resolver from a national market, which is the compatibility concern the article raises.

**「Community Discussion」** Commenters disagreed over what the episode says about anti-piracy enforcement: one argued that every anti-piracy effort short of prosecuting pirates is a backdoor to suppressing speech the government dislikes, while another said the real fix is making paid access cheaper and easier, citing a willingness to pay $2–5 for DRM-free movie downloads. A further commenter asked whether the problem is a court misreading the law or a bad law that judges are correctly applying.
